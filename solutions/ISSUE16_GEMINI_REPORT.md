# Отчёт по Issue #16 (Google Gemini 3.5 Flash Lite)

В соответствии с задачей issue #16, были проанализированы ограничения и ошибки существующего пайплайна агентских бенчмарков (`benchmark-task-agentic-github-v2bf642(1).ipynb` и связанных файлов), а также подготовлен отдельный блокнот с решением и предложениями по доработке.

## Разбор проблем из issue #16

1. **Сброс выбранной рабочей ветки между раундами**:
   - *Диагноз*: Между раундами состояние рантайма Jupyter-ноутбука/раннера сбрасывается или инициализируется заново, из-за чего переменная текущей ветки теряется, и первый `write_file` в раунде 2 уходит в дефолтную ветку (`anthropic-claude-opus-5-default`).
   - *Решение*: Использование персистентного контекста (например, запись текущей ветки в файл состояния на диск `kbench_agent_state.json`) и требование вызова идемпотентного метода `create_issue_branch(N)` в начале каждого раунда.

2. **`list_files`/`search_code`/`read_file` читают `main` по умолчанию**:
   - *Диагноз*: Функции чтения репозитория по умолчанию обращаются к ветке `main`, а не к рабочей ветке агента (`from_my_branch=False`), что заставляет агента работать с устаревшим или чужим кодом.
   - *Решение*: Изменение дефолтного параметра на `from_my_branch=True`, а также явное добавление инструментов сравнения (`diff_vs_base`).

3. **Обрезка вывода (`MAX_TOOL_OUTPUT`) на больших файлах (~50 КБ блокноты)**:
   - *Диагноз*: Жёсткое ограничение длины вывода инструментов приводит к тому, что целиком прочитать объемный JSON ноутбука невозможно.
   - *Решение*: Введение постраничного чтения (`gh_read_cursor` / `start_line` / `max_lines`), а также специализированных инструментов для работы со структурами ноутбуков (оглавление ячеек `nb_outline`, точечное чтение и замена ячеек без перезаписи всего 50 КБ JSON).

4. **Отсутствие исполнения кода и создания issues**:
   - *Диагноз*: Агент не может запустить написанный код (нет песочницы/процесса исполнения) и создавать новые issues на GitHub.
   - *Решение*: Добавление инструментов `run_python(code, timeout_sec)` для изолированного тестирования скриптов и `create_issue(title, body, labels)` для автоматизации управления задачами.
